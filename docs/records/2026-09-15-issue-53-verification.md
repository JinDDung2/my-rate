# Issue #53 구현 및 검증

## 구현

- 은행 종속 3종과 전역 5종의 타입을 분리했다. 급여·카드는 은행별 선택으로, 첫 거래는 상품별 확인으로 판정한다.
- 은행 미선택·불일치는 미확인이다. 상품별 true 오버라이드가 우선하며 같은 은행의 다른 상품에도 전파되지 않는다.
- 계산 결과는 applied / notMet / unconfirmed / excluded 4버킷이다. 기존 bp 합산·clamp·정렬 규칙을 유지한다.
- 랭킹과 액션 리스트는 같은 상품별 판정 함수를 사용한다. 미확인도 단일 조건 추가 시뮬레이션에 포함한다.
- 입력 패널은 전역 체크박스 5개와 상품 데이터에서 생성한 은행 선택 2개를 제공한다. 1위 상세에 미확인 확인 체크박스를 추가했다.
- 공유 URL은 은행명 자체를 sb/cb로 인코딩한다. 상품 목록의 인덱스 변화에 영향을 받지 않는다. 상품별 오버라이드는 공유하지 않으며, 이전 URL의 전역 은행 조건은 무시한다.
- 기능명세서 §3·§4 및 관련 기능 설명을 갱신했다. 요청에 따라 과거 작업 기록에 남은 이전 버킷 식별자도 현재 이름으로 일괄 갱신했다. 과거 기록의 검증 시점·구현 설명은 당시 맥락이다.

## Chrome 브라우저 검증

로컬 webpack 개발 서버와 격리된 headless Chrome 프로필에서 DOM 이벤트로 검증했다.

1. 실제 API 데이터: 은행 선택지 14개가 products.json의 companyName 고유값과 정확히 일치한다. 전역 체크박스는 5개이며 초기 은행은 빈 값이다.
2. 두 은행 테스트 상품을 브라우저의 `/api/products` 응답에만 주입했다. 상품 파일은 변경하지 않았다. 국민은행의 기본금리는 3%, 우리은행은 3.5%, 최대금리는 모두 5%, 급여·카드·첫 거래·자동이체 우대는 각각 20bp로 구성했다.
3. 초기 우리은행 1위 상세에 은행 종속 미확인 체크박스 3개가 표시됐다.
4. 급여 은행을 국민은행으로 선택해도 우리은행 급여는 미확인이고 금리는 3.50%였다.
5. 우리은행 급여 확인 클릭 후 충족으로 이동하고 금리 3.70%, 세후이자 96,233 → 101,732원으로 증가했다. 국민은행 랭킹 행은 동일했다.
6. 첫 거래 확인 클릭 후 해당 상품 금리가 3.90%로 재계산됐다.
7. 390px 모바일 화면에서 가로 넘침이 없었다. 화면 캡처를 확인해 충족(초록), 미확인(노랑), 미충족(회색)과 확인 체크박스 표시를 점검했다.

## 실제 데이터 수동 시나리오의 제약

상세 확인 진입점은 1위 상품뿐이다. 현재 데이터에서 국민은행 급여 선택 후 4개 기간 × 2개 적립방식 × 전역 조건 32조합을 탐색하고 카드 은행도 바꿔 보았으나, 급여이체 미확인 조건이 있으면서 금리 상승 여지가 있는 1위 상품은 찾지 못했다. 따라서 요청된 시나리오 1·2는 실제 상품 스냅샷만으로 완주하지 못했고 위 브라우저 테스트 상품으로 UI 연결을 검증했다. 실제 전체 상품의 미확인·미가산·상품 격리는 자동 테스트로 검증했다.

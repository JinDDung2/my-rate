## Findings

### 1. 이슈의 핵심 산출물(실제 배포)이 없어 Acceptance Criteria 절반이 미충족 — 현재 상태로는 제출 불가
핸드오프 Goal의 1번 산출물("실제 배포된 URL + 배포 설정 커밋")이 빠졌다. `vercel.json`과 검증 기록만 있고 `<production-origin>`은 플레이스홀더로 남아 있다. 이에 의존하는 AC가 전부 미충족이다.

- AC "Vercel 배포 + URL 기록" → **미충족** (자격 증명 없음, 문서에 blocked 기록)
- AC "배포 URL에서 조건 토글 시 새로고침 없이 갱신(수동 확인)" → **미충족** (pending)
- AC "데모 공유 URL을 배포 환경에서 열어 배지 표시 확인" → **미충족** (pending)
- AC "F-10 배포 환경에서 폴백/정상 동작 확인" → **미충족** (로컬만)
- AC "가용성: 9/7 11:00 이전 기동, 9/11까지 유지 구성 확인" → **미충족** (배포가 없어 확인 자체 불가)

정직하게 공개한 점은 인정하나, 이슈 클로즈 및 대회 제출은 배포 완료 전까지 불가하다. 기획서 헤더 마감 `2026-09-07 10:00` 기준으로 남은 시간이 약 24시간이며, 이는 문서에 "pending"으로만 적을 게 아니라 **차단 이슈로 에스컬레이션**되어야 한다.

### 2. 2차 데모 케이스(`c=SALARY_TRANSFER`)가 미검증 상태로 확정 사실처럼 기록됨
`docs/records/2026-09-07-e2e-demo-readiness.md`의 Demo URLs 표에서 `<production-origin>/?m=500000&t=12&r=S&c=SALARY_TRANSFER`에 대해 "My leader still `10-01-30-031-0036` at 3.6%; advertised leader `TD11330030000` at 4.1%; badge remains visible"라고 단정한다.

- `lib/ranking.test.ts:345`가 보장하는 것은 **우대조건 0개** 케이스뿐이다. `SALARY_TRANSFER` 선택 케이스에 대한 테스트도, 계산 근거도 문서/커밋 어디에도 없다.
- `SALARY_TRANSFER`를 체크하면 해당 조건을 제공하는 상품들의 `myRate`가 상승한다. 광고 1위 `TD11330030000`(maxRate 4.1)가 이 조건을 제공하면 `myRate`가 4.1 쪽으로 올라 세후이자가 `10-01-30-031-0036`(myRate 3.6 고정)를 추월할 수 있고, 그러면 `myLeader == advertisedLeader` → `differsFromAdvertised: false` → **"광고 1위와 다릅니다" 배지가 사라진다.** 즉 문서의 "badge remains visible"가 거짓일 개연성이 있다.
- 이 케이스가 틀리면 심사위원 앞에서 재현되는 데모 URL이 문서 설명과 다르게 동작한다.

배포 전에 반드시 실행해 확인하거나, 검증된 제2 케이스로 교체하거나, 2차 케이스를 문서에서 제거해야 한다.

### 3. Verification Log가 실제 실행 출력이 아니라 손으로 쓴 요약/생략본
- `npm test` 출력이 `# tests 81, pass 81, fail 0` + 잘린 테스트명으로 재작성돼 있다. AC는 "출력에 T1~T7 각 테스트가 pass로 찍힌 로그가 기록된다"를 요구한다. 실제 `node --test` 러너 출력(TAP/요약)을 붙여야 한다.
- evidence 재확인 명령이 `npx tsx -e "<evidence verification>"`로 스크립트 본문이 생략돼 있어 재현 불가능하다. 핸드오프 Verification 4번에 정확한 원라이너가 제공돼 있으므로 그대로 붙이고 실제 출력(`unreviewed 0 evidence-miss 0`)을 그 아래 둬야 한다.

이 리뷰 환경(샌드박스)에서는 `npm test`/`npm run build` 재실행이 차단돼 있어 리뷰어가 81 pass, `전 43건 reviewed: true`, `evidence-miss 0`을 독립 검증하지 못했다. 비샌드박스에서 실제 로그로 대체 기록 필요.

### 4. AC7(`excluded`/OTHER 조건 판정) 서술이 부정확하고 F-08 해석 논거가 얕음
DoD 표 5행: "`OTHER`/`rateBp:0` records ... are represented by the disabled `기타(계산 제외)` row".

- 실제 `condition-panel.tsx:177-182`의 `기타(계산 제외)` 행은 입력 패널에 항상 뜨는 **정적 플레이스홀더 1개**다. 개별 상품의 OTHER 조건 레코드나 그 `evidence`를 렌더하지 않는다. "represented by"라는 표현은 과장이다.
- AC7이 요구하는 "스펙 F-08 해석 포함" 판정이 빈약하다. 최소한 (a) F-08은 "각 조건 카드"를 대상으로 하며 `excluded` 조건은 카드로 렌더되지 않으므로 범위 밖, (b) `top-product-card.tsx:124-131`의 `근거 원문 보기` 토글이 `rawSpecialCondition` 전문을 노출하므로 OTHER에서 파생된 문구도 화면에서 확인 가능 — 이 두 근거를 명시해야 판정이 성립한다.

### 5. F-08 "AI 해석" 배지 무조건 표시에 대한 판정 누락
핸드오프가 명시적으로 확인을 요청한 항목("'AI 해석' 배지 무조건 표시 여부")인데, 체크리스트는 "Match"로만 처리했다. `top-product-card.tsx:30-32`는 모든 조건 행에 조건 없이 배지를 렌더한다. 이는 `data/products.json`의 모든 조건이 AI 추출 산출물(`docs/records/2026-09-03-condition-extraction.md`)이라는 근거로 방어 가능하지만, 문서는 그 근거를 적지 않았다. 판정과 근거를 명시할 것.

### 6. (경미) `vercel.json` — Node 버전 핀 없음, 키 주입 경로 문서에만 존재
`next@^16`은 Node ≥ 18.18/20 필요. Vercel 기본 런타임이 20/22라 당장 문제는 없으나 `engines` 또는 `.nvmrc`가 없어 빌드 재현성이 플랫폼 기본값에 의존한다. `ANTHROPIC_API_KEY`를 Vercel 환경변수로만 넣으라는 지침이 기록 문서에만 있고 배포 설정에는 반영 경로가 없다(수동 작업 의존). 배포 담당자용 체크리스트로 분리 권장.

## Test Gaps

- `lib/ranking.test.ts`에 우대조건 1~2개 선택 시에도 광고 1위 ≠ 내 조건 1위가 유지되는 케이스의 단위 테스트가 없다. 데모 문서가 그 결과에 의존하므로 `differsFromAdvertised: true`를 고정하는 테스트를 추가해야 한다(핸드오프 "제2 케이스" 요구사항과 직결).
- 배포 URL 기반 스모크가 전부 미실행: `GET /` 4요소, `GET /api/products` 202608·43건, 데모 공유 URL 로드 시 배지, 조건 토글 무새로고침 갱신, `POST /api/parse-situation` 503 폴백 + 서버 로그에 입력 텍스트 미출력. 배포 후 실제 수행·기록 필요.
- evidence ⊂ rawSpecialCondition 재확인이 재현 가능한 스크립트/표로 남지 않았다(명령 본문 생략).
- F-10 클라이언트 폴백은 `situation-input.tsx` 코드상 `!response.ok → 토스트 1회 + 4초 후 자동 숨김`으로 스펙과 일치함을 정적으로 확인했으나, 배포 환경에서의 실제 토스트 노출은 미확인.

## Summary

문서 `docs/records/2026-09-07-e2e-demo-readiness.md`는 구조가 명확하고 미완료 항목을 정직하게 blocked/pending으로 표시했으며, 정적 검토 범위에서 코드 레벨 주장(랭킹 컬럼 6종, F-06 배지, F-02 범위/스텝/기간/8체크박스, F-09 임계값 `>5bp = >0.05%p`, F-10 조용한 폴백+토스트 1회, F-12, 공유 URL `m/t/r/c` 포맷)은 모두 실제 코드와 일치한다.

그러나 이 이슈의 핵심 산출물인 **실제 배포가 존재하지 않아** AC 10개 중 5개(배포·수동 토글·배포 배지·배포 F-10·가용성)가 미충족이고, 현재 상태로는 대회 제출이 성립하지 않는다. 배포는 문서 각주가 아니라 즉시 해결해야 할 차단 이슈다.

추가로 (2) 2차 데모 케이스가 미검증 상태로 확정 사실처럼 기록됐고 배지가 사라질 개연성이 있어 데모 전 실행 확인이 필수, (3) 검증 로그가 실제 출력이 아닌 요약본이라 AC의 "T1~T7 pass 로그 기록" 및 evidence 재확인 요구를 형식적으로만 만족한다, (4)(5) AC7·F-08 배지 판정의 근거 서술이 부정확하거나 누락됐다.

병합 자체는 회귀 없는 문서/설정 추가이므로 가능하나, **이슈 클로즈는 배포 완료 + 배포 기반 스모크 기록 + 2차 데모 케이스 검증 전까지 불가**하다.

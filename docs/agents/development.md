# Development Rules

개발 작업에서 필요한 규칙만 모은다.

## Workflow

1. 관련 파일과 기존 패턴을 먼저 읽는다.
2. 변경 범위를 작게 잡는다.
3. 도메인 로직은 테스트 가능한 단위로 분리한다.
4. 구현 후 테스트, 빌드, 린트 중 가능한 검증을 실행한다.
5. 변경 파일, 검증 결과, 남은 리스크를 짧게 보고한다.

## Engineering Preferences

- 기존 코드 스타일과 프레임워크를 우선한다.
- 불필요한 추상화보다 명확한 도메인 모델을 선호한다.
- 금융 계산은 부동소수점 오차를 피하고 정수 또는 decimal 계열 타입을 검토한다.
- 날짜, 통화, 세율, 외부 데이터 시점은 경계에서 명시적으로 다룬다.
- 자동 생성 파일과 수작업 파일의 경계를 분리한다.

## Git

- 사용자가 만들었을 수 있는 변경을 되돌리지 않는다.
- 파괴적 명령은 명시 요청이 있을 때만 실행한다.
- 커밋 요청이 없으면 커밋하지 않는다.
